別のセッションで作業を再開する時に最初に読む資料。ゲームの仕様・作り・決めたこと・ツール・次にやることをまとめている。
ツールの使い方は [tools/README.md](tools/README.md)。

- プロジェクト: `D:\test1\mumu`（Unity 6000.0.58f2、UGUI、UniTask、Unity Localization、TextMeshPro）
- 最初のシーン: `Assets/mumu/Scenes/system.unity`（`SystemManager` → タイトル画面）
- タイトル: **つなパグ** / Pug Path（キャッチコピー「パグまで道をつないで、たすけだそう！」）
- 方向性: **シンプル・中毒性・ピクセルアートでかわいい**。タイマー・ライフ・スタミナ・失敗させる手数制限は入れない（いつでも戻せる、のんびりした遊び心地を大事にする）

## 1. 作業のルール（ユーザーの好み）

コーディング規約（`c:\workspace\client\CLAUDE.md` と同じものをこのプロジェクトにも使う）:
- XML コメントの `<summary>` は短く。`<param>` は空のまま（`/// <param name="_data"></param>`）
- メソッドの引数は `_` で始める、private のメソッド・フィールドは小文字始まり、列挙型は `e` で始める（`eBlockType`）
- 外から受け取ったコールバックはボタンに直接登録しない。フィールドに持って、private の押下処理メソッドから呼ぶ
- **「Generated by Claude Code」のコメントは付けない**（ユーザーが消した）。コメントは最小限
- UnityEngine.Object の null チェックは `!= null`（`?.` や `??` は使わない。fake null 対策）
- 仮の ID・借りたデータは定義と使う所すべてに `// TODO:` を書く
- 日本語のゲーム内テキストはひらがな多めで、単語の間にスペース（例「きょうの おさんぽ 5回が おわったよ。」）

進め方:
- 大きな機能を頼まれたら、まず「理解したこと・やること・確認したいこと」を短く返して、OK をもらってから作る（ユーザーがよく「repeat what you understand first」と言う）
- 返事はユーザーの言語に合わせる（日本語・英語が混ざる）
- 画像は Unity の外でジェネレーター（tools/art）を使って作り、プレビュー画像を見て確認してから入れる
- 変更したら `tools/scripts/verify_build.ps1` でコンパイルを確認する（Unity を開かなくても確認できる）
- プレハブは手で YAML を書かず、エディタのビルダー（`Scripts/Editor/*Builder.cs`）で組み立てる
- **UI のルール**: 既にある UI を直す時は、Claude はコードを編集せず、直す箇所と内容を伝える（ユーザーが直す）。新しい UI は作ってよいが、UI パーツ（Image・Text・Layout など）を実行時に `new GameObject` / `UiFactory` で作らない。Resources のプレハブを読み込む（`PartsLoaderManager` / `PopupLoader` / `ResourceManager`）。スクロールの項目も Resources から読む（ずかんの `PugBookScrollItem` の形）
- **プレハブは直接編集**: 作ったプレハブはユーザーが Unity で直接直す。ビルダーは未作成のものだけ作り、作成済みのプレハブは上書きしない
- **UI プレハブは追加・編集しない**: UI のプレハブ（Resources/Prefabs の View・Popup・Common など）は Claude が作ったり書き換えたりしない。必要なものは「どのプレハブに・何を・どう置くか」を伝えて、ユーザーが Unity で作る。UI の見た目を変えたい時も同じ（コードの UI も既存は直さず、直す箇所を伝える）

## 2. ゲームのルール

- 一筆書きパズル。Start から上下左右に1マスずつ経路を伸ばし、Goal に着いたらクリア。自分の経路は横切れない
- 指を離しても経路は残る。経路上のどこかを押すとそこまで巻き戻して、そこから続けられる。1つ前のマスに戻るとアンドゥ
- **巻き戻しの範囲**: 指を離さずドラッグ中は、経路上なら1つ前のマスにだけ戻れる（5→4→3…と一歩ずつ。`InGameMap.DragStep`）。指を離してから押し直すと、経路上のどのマスへも戻れる（`InGameMap.GetPressTarget` → `PuzzlePath.MoveTo`）。ワープの入口・こわれる橋より前には戻れない
- **ドラッグ（方向で進む）**: 押した場所が経路上・次に進めるマス・先端付近（`NoDragRange` = 2 マス以内）・背景のどこでも、1本指ならドラッグを始める（経路ドラッグ）。経路上を押すと、そのマスまで巻き戻してそのままドラッグ開始（次に進めるマスなら進めてから）。起点から半マス分（`DragStepRate` = 0.5、ローカル座標なので拡大縮小しても同じ）動くと、一番近い斜めの向き（マップの 4 方向＝画面の斜め）へ1マス進む。進んだら起点を今の位置に移す。1マスごとに `DragDelayPerBlock` = 0.1 秒待つ（待っている間は起点を動かさないので、指を止めていても溜まった分が進む）。進めない向きなら何もしない（先端が揺れるのは `DragStep` の `Refused`）。タイルの当たり判定は押した時だけ使い、ドラッグ中は使わない（`MapInputController.dragPath` → `MapPathInput.TryGetDragDirection` / `DragStep`）。数値は `Resources/Settings/MapInputSettings.asset`（`MapInputSettings`）
- **ドラッグ中の線**: 先端から指の移動量だけ黄色い線を出す（`MapInputController.showDragPreview`）。指が動いていない時は先端の上に小さな点。先端が変わったら線は点に戻る
- **2本指に切り替え**: ドラッグ中に2本目の指を置くと経路のドラッグは一時停止し、先端は1本目の指の位置へ移る。2本指で移動・ピンチ。残った1本の指で離すと、そのまま経路のドラッグを再開する（`pauseRouteDrag` / `resumePathDrag`）
- **Goal の解放**: 通ったマス数（Start・Goal を除く）が `ウェイポイント数 × 解放率` 以上で Goal に入れる。解放率は難易度で 60%（Lv1）→ 72%（Lv20）→ 84%（Lv40）→ 90%（Lv50）。足りない時に Goal に入ろうとすると「Need N」と揺れる
- **チェックポイント**: 設計した経路の 25% / 50% / 75% の位置。★が浮いていて、通ると回りながら跳ねる
- **★**: クリア時に通ったチェックポイント数で ★3（全部）/ ★2（1つ足りない）/ ★1
- **PERFECT（王冠）**: ★3 かつ 通ったマス数 ≥ 設計した経路の長さ（必ず達成できる条件にしている。全マス埋めは一筆書きできないマップがあるので使わない）
- 主人公: 男の子のパグ（青い首輪）。経路の先端に座っていて、ドラッグすると線に沿って走る（遅れるほど速く、2マス以上巻き戻すとジャンプ）。チェックポイントで跳ねる
- Goal: 泣いている女の子のパグ（ピンクのリボン、ご褒美ステージではそのキャラ）。男の子が 3 マス以内に来ると泣きやんでこっちを見る
- クリア演出: 2匹に寄る → 2匹が喜ぶ → ブロックが順に跳ねる → ★ → 紙吹雪 → 札が CLEAR!/PERFECT! にめくれる → 報酬ダイアログ → 黒フェードで次へ

操作:
- マップ移動は **2本指のドラッグ**（実機）。1本指のドラッグは経路を進める。ピンチ／ホイールで拡大縮小
- エディタでは **Space を押しながらドラッグ** でマップ移動（Space を押すと経路のドラッグは一時停止する。離すと再開）
- 先端の周りを自動で寄せる: ドラッグ中、先端が画面の端から 10%（`AutoFocusEdgeMarginRate`）以内に入り、さらに端の方向へ動いている時、今の倍率で先端を中央へ寄せる。連続しないよう 0.75 秒の待ち時間（`AutoFocusCooldown`）
- 進めない時（ギミックの決まり違い・扉・Goal 未解放）は先端のブロックが横に揺れて Refused 音。揺れは `Block.PlayShake` で、重なっても元の位置からずれない（`UiTween.ShakeX` は元の X を引数で受け取る）
- ダブルタップで先端に寄る（全体が入る倍率）。ドラッグで先端が変わったら今の倍率のまま先端に寄る
- マップを開いた時は Start を中心に表示

## 2.5 ギミック

マスに置く `eBlockSubType`（1マスに複数可、通り方のギミックは1つだけ）。マップ CSV の 5 列目 `gimmick` に名前を `;` 区切り。
- **やじるし**（ArrowUp/Down/Left/Right、Up = y-1 = 画面の奥）: 矢印の向きにしか入れず、同じ向きにしか出られない（まっすぐ通り抜ける）
- **まがる**（Turn）: このマスで必ず曲がる / **まっすぐ**（Straight）: まっすぐ通り抜ける。判定は出る時
- **宝箱**（Treasure1 木 = ほね 2 / Treasure2 銀 = 4 / Treasure3 金 = 10）: 通ると開けて拾う（巻き戻すと戻る）。★・PERFECT・Goal 解放には関係なし。**自動生成のマップには必ず1つ**（設計した経路の上、木 60% / 銀 30% / 金 10%、`MapGenerator.TreasureWeights`）。クリアで `save.bones` に加算。冒険はステージごとの最高数より多く拾った分だけ（くり返し稼げない）、おさんぽは拾った分全部。ヘッダーに「拾ったほね/マップのほね合計」、おにわのヘッダーに合計。ほねのギミック（Bone）は廃止
- **カギと扉**（KeyRed/Blue/Yellow・GateRed/Blue/Yellow）: 扉は同じ色のカギを経路で通るまで入れない（巻き戻すと閉じる）。扉は立った柵、開くと倒れる。カギはほねと同じく浮かんで拾う。閉じた扉へ進むと画面下に「カギを とってから とおろう」
- **ワープ**（WarpIn*/WarpOut*、色ごとに入口1・出口1）: 一方通行。入口に乗ると出口へ飛ぶ（入口と出口の2マスが経路に入る、線は引かない、男の子はぴょんと移る）。出口がもう経路上なら入口は普通のマス。入口を押して巻き戻すと入る前まで戻る（`PuzzlePath.warpJumps`）
- **こわれる橋**（Crumble）: 降りると壊れ（板が落ちてブロックが暗くなる）、そのマスとそれより前には戻れない（`PuzzlePath.LockedIndex`）。やりなおしはメニューの Retry。初めて壊れた時と、戻ろうとした時に画面下のお知らせ（ダイアログは出さない）
- 1マスに1つだけ: やじるし・まがる・まっすぐ・扉・ワープ・こわれる橋（`GimmickUtility.IsExclusive`）。宝箱・カギは一緒に置ける
- 画面下のお知らせ: `InGameMap.SetOnMessage(key)` → `GameView.showToast`（TOAST_GATE / TOAST_CRUMBLE / TOAST_CRUMBLE_LOCKED）
- 交差する橋は見送り- 決まりに合わない方向へは進めず、先端が揺れて Refused 音（`PuzzlePath.isGimmickAllowed` / `IsBlockedByGimmick`）
- 見た目: やじるし・まがる・まっすぐは上面に寝かせたアイコン（線の下）、ほねは浮かぶ（`Block.applyGimmicks`）
- `MapData.ValidatePath` が設計の経路がギミックの決まりを守っているかも調べる（ギミックは Walkable だけ）
- 自動配置 `MapGenerator.PlaceGimmicks(mapData, GimmickCounts, random)`: 設計の経路に合うマスへ（やじるし・まっすぐ = 経路がまっすぐなマス、まがる = 曲がるマス、ほね = 経路上と少し経路外）。ほかに進める道が多いマスほど選ばれやすい。`Generate(..., GimmickSettings)` で生成時にも置ける（数は `GimmickCounts.FromPath`）
- `MasterData/gimmick.csv`: `id,key,name_ja,name_en,desc_ja,desc_en,sprite,unlock_stage`。マップで初めて見たギミックは説明ダイアログ（`save.seenGimmicks`）。おさんぽは冒険で unlock_stage をクリアしたギミックだけ使う（`GimmickMaster.GetStrollSettings`）
- マップエディタ: Gimmick モード（Arrow Auto = 経路から向きを自動、各向き、Turn、Straight、Treasure1〜3、Key/Gate/WarpIn/WarpOut（赤・青・黄）、Crumble、Erase。左で置く・同じものを押すと外す、右でそのマスを全部消す）、Auto Place（数と seed、Suggest でおすすめの数）、Clear Gimmicks、Generate の Gimmick トグル。Waypoint モードは経路上を押すとそこまで戻して続きから描ける

## 3. 画面と流れ

```
system.unity → Title
Title ─ 冒険   → (全クリア済みならお知らせ) → StageMap ─ あそぶ → Game ─ クリア → StageMap（次のノードまで走る）→ …
      ├ おさんぽ → (今日のチャンス 0 ならお知らせ) → Game ─ クリア → Game（次のおさんぽ）→ …
      ├ おにわ   → Garden
      └ ⚙       → 設定ポップアップ（SE / BGM）
Game の ☰ → 設定ポップアップ（SE / BGM / やりなおす / タイトルへ）→ はい／いいえ の確認
```

- **冒険**: map_list.csv の順。**今は 500 ステージ**（`tools/mapgen` で作ったテスト用。リリース用の本番ステージはまだ。ステージ数の上限はない）。10 ステージごとにテーマ 1〜14 を繰り返し（1〜10 そうげん、11〜20 なつ、…）、10 ステージごとに難易度 +1（1〜10 = 1、491〜500 = 50）。ステージ 1 は手で作った分かれ道のない一本道（ギミックなし）。

**ギミックのルール（ユーザー指定・確定）**
- ステージ 1、11、21、31… は手で作った**まっすぐな一本道**で、ギミックはなし。
- 新しいギミックは **10 レベルごと**（= 10 ステージごと）に 1 つ増える。新しいギミックが出るステージは、必ずまっすぐな一本道。
- それ以外のステージは、それまでに覚えたギミックからランダムに使う（ひとつも使わない時もある）。
- ⚠ 現在のコード（`tools/mapgen/Program.cs` の `buildTutorial`）はまっすぐではなく「くねくねの一本道」で作っている。上のルールに合わせるなら直す（要確認）。

新しいギミックの順（11, 21, 31… に 1 つずつ。順に やじるし上 → あかい カギ → あかい ワープ → やじるし下 → あおい カギ → あおい ワープ → まがる → やじるし左 → きいろい カギ → きいろい ワープ → まっすぐ → やじるし右 → こわれる橋。131 まで）。それ以外は、それまでに覚えたギミックからランダムに使う（ひとつも使わない時もある）。宝箱はステージ 1 以外に 1 つずつ。作り直しは `tools/scripts/run_mapgen.ps1`（`tools/mapgen/Program.cs` の `Schedule`。実行すると MapData を上書きする）。**500 をクリアした後の扱いは未確認**。全クリア後に冒険を押すと毎回お知らせダイアログ。アップデートでステージが増えたら未クリアの先頭から再開
- **ステージマップ**: 10 ステージで 1 ページ。次のページへ進んだ時はページが下から上がってきて、男の子が下から走ってくる。くねくねの道（肉球）とノード（クリア=緑、今=黄色で脈打つ、まだ=グレー）、クリア済みは★と王冠。背景・BGM は今のステージのテーマ。クリア後は男の子が次のノードまで走る（ページをまたぐ時は走らない）
- **おさんぽ**: 1日 5 回は日替わりシード（日付と回数から決まる、同じ日の同じ回は誰でも同じ）で、クリア時 20% でノーマルパグがもらえる（抽選はマップを決めた時、当たりなら Goal でその子が待つ、やりなおしても同じ）。回数はクリアで数える。6 回目からは完全ランダムで報酬なし。5 回目のクリア後と、その後にタイトルで押した時にお知らせ。難易度は冒険の今の難易度 ±10。札は「おさんぽ 2/5」→ 以降「ステージ ???」
- **ずかん**: おにわの下のボタンで大きなポップアップ。全キャラのグリッド（tier の色の台・★・持っている数・まだの子は NEW・交換ボタン）。押すと はい／いいえ で確認してほねと交換（`PugBookPopup`、Prefabs/Popup/pug_book）。交換したらおにわを開き直して新しい子を出す
- **おにわ（箱庭）**: 10x10 の草原にもらったパグ全員（重複も、最大 30）が座る・1〜4 マス歩く・お昼寝（目を閉じて z が浮かぶ、15%）・ほかの子のとなりまでついて歩く（ときどき）を繰り返す。となり同士で座るとハート。タップで起きて跳ねて名前の吹き出し
- ゲーム画面のヘッダー: Goal 解放までの残りゲージ（数が減るとハートが上がる、左端に Goal の子）・王冠・★3・メニューボタン・下にステージ札
- **横切る生き物**: ゲーム・タイトル・おにわで 6〜14 秒ごとにテーマの生き物が横切る（`AmbientCritters`、テーマとの対応は `ThemeDefine.GetCritter`）
- 画面切り替えは `ViewManager`（`Resources/Prefabs/View/{eViewType}`）。フェード付きは `ToNextStage` / `RetryStage` / `ToTitleWithFade` / `ToStageMapWithFade` / `ToGameWithFade`
- **雰囲気の粒**（`AmbientParticles`）: テーマごとのプレハブ `Prefabs/Ambient/ambient_{id:000}`（ParticleSystem、レイヤー `UI`、Sorting Layer `Effect`）を `EffectManager` の `effectRoot` の下に出す。同時に1つだけ（新しく出す時に前のものを消す）。粒の動き・色・大きさはプレハブで直す（コードは出す範囲だけ決める）。夜のテーマは別プレハブ（20〜32）。office（14）は粒なし。`AmbientParticlesBuilder` は未作成のプレハブだけ作る
- **描画順（目標）**: Game < Effect < UI。Game = views（マップ・ガーデン・ステージマップ）、Effect = 雰囲気の粒（ワールド空間の ParticleSystem）、UI = ヘッダー・ポップアップ・お知らせ。粒はマップのブロックより上に出る（以前はブロックの下だった）
  - Unity での作業（まだ）: system シーンの Canvas を **Screen Space - Camera**（Render Camera = Main Camera）にする。viewRoot に Canvas（Override Sorting、Sorting Layer `Game`）、uiRoot と notificationRoot に Canvas（Override Sorting、Sorting Layer `UI`）、ゲーム画面のヘッダーも入れ子の Canvas（`UI`）にする。粒は `Effect` のまま
  - Overlay のままだとワールド空間の粒は UI の下に出るので、この作業が必要

## 5. データ形式

すべて UTF-8（BOM なし）の CSV。読み込みは `CsvUtility`（クォート対応）。

### map_list.csv（冒険の並び順）
`id,name,themeId,width,height,difficulty`（difficulty は省略時 1）

### maps/map_XXXXXX.csv（1 マス 1 行）
`x,y,type,waypoint` — type は eBlockType の名前、waypoint は 1 始まりの経路順（空欄 = 経路外）。y=0 が画面の奥。書かれていないマスは Empty

eBlockType: `Empty=0, Walkable=1, Obstruct1=2, Start=3, Goal=4, Water=5, Obstruct2=6, Obstruct3=7, Obstruct4=8, Bridge=9`
- Walkable と Bridge が通れる。Obstruct1〜4 は通れないブロックで、テーマの土台 11 を使う（デコは出さない）。Start・Goal の周り 3x3 の障害物はデコを出さない（隠れないように）

### MasterData/character.csv
`id,name_ja,name_en,sprite,tier,fur,outfit,marking`
- **501 匹**: tier1 177 / tier2 169 / tier3 114 / tier4 19 / tier5 20 / tier6 2（500 パグツー、501 パグワン）。1〜149 は名前つき、150〜499 は仮の名前 `毛色[-模様]_衣装_tier_id`（あとでユーザーが直す）
- 毛色 24（ふつう 17: fawn, black, cream, apricot, silver, mocha, peach, smoky, caramel, honey, ash, ginger, sand, cocoa, rose, mint, lilac / 特別 5: golden, pink, sky, chocolate, white / tier6: violet, bubblegum）、衣装 32、模様 3（none / white = 胸と顔が白 / spots = ぶち、ぶちは tier +1）
- tier5 = 特別な毛色 × 特別な衣装（王冠・桜・天使の輪・魔女・イヤーマフ）の残り 20 通り
- 値段（ほね）: 200 / 500 / 1000 / 5000 / 20000 / 交換不可。おさんぽで当たった時の重み（0.001% 単位、合計 100000）: 59400 / 28000 / 10000 / 2000 / 500（0.5%）/ 100（0.1% = 1匹 0.05%）（`CharacterMaster.TierPrices` / `TierWeights`）
- **重複はほね**: 持っている子をまたもらったら、代わりに tier ごとのほね 5 / 10 / 20 / 50 / 500 / 10000（`DuplicateBonesByTier`）。ダイアログ「もう なかまだよ！」。持っている子はずかんで交換できない（「もってる」）。仲間は1匹ずつ
- **tier5・6 はキラキラ**（`PugAura`、tier5 金・tier6 虹色）: おにわ・Goal・連れていくパグ・ずかん・なかまダイアログ
- **連れていくパグ**: おにわでパグをタップ → 吹き出しの「つれていく」（連れていく子は頭に★、もう一度押すと「はずす」で男の子に戻る）。冒険・おさんぽの経路を走る子とステージマップの子がその子になる（座る・歩く＝走る・喜ぶ）。`save.equippedPugId`（0 = 男の子）
- sprite: `Resources/Sprites/Pugs/{100 匹ずつのフォルダ 000,100,…}/{sprite}.png`（等倍 128x128、表示する子だけ読み込む。atlas にしないのはメモリのため）。ずかんはアイコン集 `Sprites/PugIcons/pug_icons_N.png`（icon_XXX、`PugIcons.Get`）と tier タブ（選んだ tier のカードだけ作る）
- fur・outfit・marking は画像を作る時のメモ（ゲームは使わない）。`run_pug_gen.ps1` がこの 3 列から画像とアイコン集を作る
- 手に入れ方: **おさんぽ**のクリア時（1日5回、20% で当たり → tier の重み → その tier から均等）と、おにわの**ずかん**でほねと交換（まだ持っていない子を選ぶ）。冒険ではもらえない
- 保存データ version 2: パグツー・パグワンの ID を 150・151 → 500・501 に直し、重複していた子はほねにする

### save.dat（`Application.persistentDataPath/save.dat`、暗号化）
`UserSaveData`（version 1）:
`isSeEnabled, isBgmEnabled, stageIndex, clearedCount, stageRecords[{stage, stars, isPerfect, bones}], pugs[], dailyStrollDate(yyyyMMdd), dailyStrollCount, bones, seenGimmicks[]`
- 読み書きは `SaveDataManager`（変更のたびに保存、tmp に書いてから差し替え）。形式を変えたら `UserSaveData.CurrentVersion` を上げて `SaveDataManager.migrate` に変換を足す
- 新規ユーザーはパグ 1（むぎ）を持っている（`SaveDataManager.DefaultPugId`）
- 前の版の PlayerPrefs（`mumu.*`）は初回に自動で移して消す
- **暗号化**: `SaveCrypto`（AES-256-CBC、保存ごとにランダムな IV、改ざんチェックに HMAC-SHA256、形式 `MUMU1` + Base64）。鍵は `SaveCrypto.Secret` から作る（**リリース前に変える。変えると今までの保存データは読めない**）。読めない・書き換えられたファイルは `save.dat.broken` に残して新しく始める。前の版の `save.json`（暗号化なし）は初回に読み込んで暗号化し直して消す
- 中身を見る・書き換える時は mumu > Save Data > **Export JSON**（`save_debug.json` に書き出して開く）→ 編集 → **Import JSON**

## 6. 画像・音の決まり

- テーマ（`ThemeDefine`、19 個）: 1 meadow, 2 summer, 3 winter, 4 autumn, 5 spring, 6 sakura, 7 desert, 8 cake, 9 pudding, 10 city, 11 village, 12 sea, 13 ice, 14 office, 15 space, 16 underwater, 17 moon_forest, 18 castle, 19 mountain（それぞれ雰囲気のパーティクル設定あり）。マップ生成（mapgen）は今 1〜14 だけを使う
- テーマ画像 `Sprites/Themes/theme_XXXXXX/XXXXXX_N`: 0 未通過 / 1 通過済み / 2〜5 高いデコ（木・4コマのシート、676x281、1コマ 169x281）/ 6〜9 静止画のデコ（169x281）/ 10 水 / 11 通れないブロックの土台（`Block.ObstructTint` で暗く表示）/ 12 橋 / bg 背景タイル
- **デコの大きさ（静止画 6〜9）**: ブロックの中に 5 px ずつ余白を空けて収まる。幅は最大 50 units（ブロック 60 − 左右 5）。縦横の比は保つ。大きくしない。テーマ 1 が基準
- **木（2〜5）**: 基本は テーマ 1 の木の形。葉の色はテーマごと（ブロックの色と名前に合わせる。1 テーマの中でも色を変える）。木の大きさはテーマ 1 と同じ
- **特別なテーマ（葉の代わりに中身）**: 8 cake（ケーキ・ろうそく・キャンディ・はちみつ、テーマ 8 は承認済み）、27（ケーキと同じ）、9・28 pudding（クリーム・いちご）、14・33 office（秋の色の木）、15 space（地球・太陽・月・星）、13・31・32 ice（葉のない木の枝、雪）、10・29 city（普通の木）
- デコの出し方: マップの外の後ろ2マス（左上・右上の辺）に枠。外側は高いデコ、内側は 60% 小さい・普通、20% なし、20% 高い（`MapBlockView.buildRing`、位置とテーマのハッシュで毎回同じ）。マップの中の通れないブロックは平らな土台だけ（デコなし）
- **デコの影**: 枠（`RingBlock`）の `decoShadow`（プレハブの子 Image、Sprite は `deco_shadow`）。デコの根元の下に薄い楕円を出す。プレハブの割り当ては手作業（`ring_block.prefab` の RingBlock の Deco Shadow）
- 夜のテーマ（20〜33）は昼のテーマをコピーせず、それぞれのテーマの木・デコを使う（テーマごとの色）
- ブロックはアイソメ。`posX = (x - flippedY) * 30`, `posY = (x + flippedY) * 15`（`flippedY = h-1-y`）、ブロック 60 units、上面判定はひし形、持ち上げ `MapLayout.RaiseHeight` = 6 units（通れないブロックも持ち上がる。浮いて見える点は未解決）、描画順 `SortIndex`
- パグのシート: tools/README.md 参照。表示サイズ 44px、pivot (0.5, 0.08) で足元を上面の中心に
- SE（`eSe`、`Sound/SE/se_{6桁}`）: 1 Click（ボタン）/ 3 Bark2（進めない）/ 4 BlockGain（1マス進む）/ 5 BlockGain2（チェックポイント・Goal 解放）/ 6 BlockMinus（巻き戻す）/ 7 WinJingle（クリア）/ 28 AlertChime（今日のおさんぽが終わった）など、全部は `eSe`（`Scripts/Core/Managers/SoundManager.cs`）。`MumuButton` はクリックで Click 音を鳴らす（インスペクターで音の変更・無効化、暗幕は無音）
- BGM（`Sound/BGM/bgm_{3桁}`）: タイトルは 000（`SoundManager.TitleBgmId`）、テーマ ID 1〜14 は bgm_001〜014、曲のないテーマは 000。おにわはテーマ 1。同じ曲なら流し直さない。bgm_999 は使っていない

## 9. マップ生成・マップエディタ

- `MapGenerator.Generate(mapData, difficulty 1〜50, eMapPattern, seed, ...)`（同じ seed なら同じマップ）

- マップエディタ（Map > Edit）: マップ選択・New / Copy / Save / Reload、名前・難易度・テーマ、Visual 表示（アイソメのプレビュー）、Generate（難易度・形・seed）、マス・経路の編集
